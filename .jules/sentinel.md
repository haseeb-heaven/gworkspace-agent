## 2024-05-24 - Avoid shell=True with Subprocess\n**Vulnerability:** Found `shell=os.name == "nt"` being used with a command list in `subprocess.run` inside `framework/task_runner.py`.\n**Learning:** Passing a list with `shell=True` is dangerous because on Windows it still triggers shell interpretation, whereas on POSIX it treats the first item as the executable and the rest as arguments. This introduces both unexpected behavior and security risks (shell injection) if any of the list arguments contain metacharacters. In `framework/task_runner.py`, we're running `sys.executable -m pytest ...`.\n**Prevention:** Never use `shell=True` unless absolutely necessary and providing a single string command. For platform-independent `subprocess` calls, just pass the list with `shell=False`.
