## 2024-05-18 - subprocess shell=True vulnerability on Windows
**Vulnerability:** The codebase was found to be using `shell=os.name == "nt"` in `subprocess.run()`. This enables `shell=True` on Windows environments, which introduces a severe command injection vulnerability if the command list includes unsanitized user inputs or environment variables.
**Learning:** Developers often mistakenly believe `shell=True` is required on Windows to run executable files like `sys.executable` or `pytest`. In Python's `subprocess` module, passing a command as a list (e.g., `["python", "-m", "pytest"]`) executes the binary directly without needing the shell, making `shell=False` completely safe and fully functional across all operating systems.
**Prevention:** Never use `shell=True` (or expressions that evaluate to `True` such as `os.name == "nt"`) in `subprocess` unless explicitly intending to execute built-in shell commands (like `dir` or `echo`) and only when strictly necessary. Always pass arguments as lists with `shell=False` (which is the default).
